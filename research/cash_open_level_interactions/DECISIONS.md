# DECISIONS.md — generation 8 (cash-open level interaction study)

These are implementation-level judgment calls required to execute Dylan's
frozen methodology exactly; none alter its substance, thresholds, or
scope. Every choice is disclosed here per the project's standing
discipline.

| # | Decision | Rationale |
|---|---|---|
| 1 | New branch `research/cash-open-level-interactions` from `research/cash-open-level-library` @ `3c734ca`; generations 1-7 untouched | Per instruction |
| 2 | `scipy`/`statsmodels` installed into the environment (not present); no project dependency-lock file exists to update | Needed for Wilcoxon signed-rank and exact McNemar; feasibility-check finding, reported before preregistration commit |
| 3 | Outcome storage is long-format (one row per event×horizon for D/MFE/MAE/Q/close-recross/labels; one row per event×horizon×k for barriers), not wide-column-per-horizon | Equivalent information content, far more tractable to generate/query/test at 76 (instrument×level_id) × 2 arms × up to 1291 sessions scale; the frozen spec does not mandate a storage shape |
| 4 | Orientation, `dir`, `side_scale` computed per `(session, level_id, ARM)` using that arm's own `V` vs `O_0930` | Family B explicitly requires "both arms have the same non-ambiguous orientation," which presupposes orientation is an arm-level, not unit-level, property |
| 5 | If `scale_U`/`scale_D` are unavailable, orientation is stored as `NA` (distinct from `AT_OPEN_AMBIGUOUS`, which means the level sits within `τ_b` of the open on a *valid* scale) | Keeps "genuinely near the open" separate from "orientation not computable"; both are excluded from normalized outcomes and Family B, but for different, separately diagnosable reasons |
| 6 | `directional_close_recross`: the continuation-side and rejection-side close search uses **strict** inequality (`close > V` / `close < V`); a close exactly equal to `V` counts as neither | Avoids an arbitrary tie-breaking rule not specified by Dylan; a close exactly at the level is descriptively neutral |
| 7 | Barrier `barrier_order_h_k`: if only one barrier is reached within the horizon, it is labeled `CONTINUATION_FIRST`/`REJECTION_FIRST` (the other simply never occurred in-window, not tied); both-reached-same-bar → `SAME_BAR_BARRIER_TIE`; neither reached → `NEITHER_REACHED` | Matches the four allowed labels exhaustively without inventing a fifth "one-sided-only" category |
| 8 | Cluster/co-touch checks use the **raw touch condition** (`Low≤V≤High` at the specific bar) against every other level's `V`, not that other level's own recorded first-touch bar | A bar can satisfy the touch condition for level B even when B's own first touch (pre-consumption) happened earlier; using the raw condition at the exact bar in question is the correct, consumption-independent co-touch test |
| 9 | `pair_separated` and both isolation checks use `0.10 × side_scale` where `side_scale` is each check's own focal arm's `side_scale` (real arm's for `real_isolated`/`pair_separated`; synthetic arm's for `synthetic_isolated`) | Dylan's spec says "0.10 * side_scale" without specifying whose scale when arms could (rarely) differ in orientation; using each check's own focal arm keeps every flag self-consistent with that arm's own directional frame |
| 10 | Family A CI: normal-approximation (Wald) CI on the paired touch-rate difference (`SE = sqrt(n01+n10 − (n01−n10)²/N)/N`) and on the log discordant-pair odds ratio (`SE = sqrt(1/n01+1/n10)`, 0.5 continuity correction if either count is 0) | Standard, transparent, closed-form; avoids introducing an undisclosed resampling method for the primary confirmatory family |
| 11 | Family B CI: percentile bootstrap (2000 resamples, fixed seed `20260712`) on the Hodges-Lehmann paired-location estimate | The exact rank-based HL confidence interval requires a lookup procedure not available without a bespoke implementation; a seeded, reproducible bootstrap is disclosed as the method, not presented as the exact nonparametric CI |
| 12 | McNemar test computed via `scipy.stats.binomtest(n01, n01+n10, 0.5)` (exact two-sided), not `statsmodels.stats.contingency_tables.mcnemar` | Identical statistic (exact McNemar *is* the exact binomial test on discordant pairs); avoids an extra dependency for no methodological gain |
| 13 | `AT_OPEN_AMBIGUOUS`/orientation-`NA` sessions remain in touch-rate (Family A) and raw-displacement diagnostics, per §6 of the frozen spec, but are excluded from every normalized/directional outcome and from Family B | Verbatim from the frozen spec; recorded here only to confirm no additional exclusion was added beyond what was specified |
